# ขั้น 8 — ขัดเกลา + ตรวจคุณภาพ

> วางพรอมต์ด้านล่างนี้ให้ AI

---

อ่านกฎกลาง แล้วทำ **ขั้น 8 เท่านั้น**: ตรวจและแก้ทั้งเว็บให้ได้มาตรฐานก่อนเชื่อม Backend **ห้ามเพิ่มฟีเจอร์ใหม่**

## งาน
1. **ตรวจ Responsive** ที่ความกว้าง 360, 390, 768, 1024, 1280 ทุกหน้า: ไม่มีแถบเลื่อนแนวนอน, ไม่มีข้อความทับ/ถูกตัด, ตาราง/โค้ดยาวเลื่อนในกล่องของมันเอง, แถบเมนูล่างไม่บังเนื้อหา (เผื่อ `padding-bottom` และ `env(safe-area-inset-bottom)`)
2. **ตรวจธีมสว่าง** ทุกหน้า: คอนทราสต์ตัวอักษร ≥ 4.5:1 (ตัวใหญ่ ≥ 3:1) ทั้งสองธีม เขียนสคริปต์เล็ก ๆ `tests/contrast-check.html` ที่เดินทุก element ที่มีข้อความแล้วรายงานคู่สีที่ไม่ผ่าน (ใช้ `getComputedStyle`)
3. **ตรวจการเข้าถึง**: ใช้คีย์บอร์ดล้วนทำครบโฟลว์ (login → เลือกวิชา → Quiz → เฉลย → ออกจากระบบ), ลำดับ Tab สมเหตุผล, ทุก `<img>`/ไอคอนมี alt/aria, หน้าแต่ละหน้ามี `<title>` และ `<h1>` เดียว, landmark (`header/nav/main`), ข้อความสถานะอ่านโดยโปรแกรมอ่านหน้าจอ (`aria-live`), เคารพ `prefers-reduced-motion`, ซูมเบราว์เซอร์ 200% ใช้งานได้
4. **ตรวจหลายภาษา**: `tests/i18n-check.html` (หรือสคริปต์ Node ถ้าผมอนุญาต) เทียบ key ของ `lo/th/en.json` ว่าครบเท่ากัน, หา key ที่ใช้ในโค้ดแต่ไม่มีในไฟล์, และหาข้อความตายตัวที่หลุดอยู่ใน HTML/JS (ยกเว้นข้อมูลจาก API) แล้วแก้ให้หมด
5. **ตรวจความปลอดภัยเบื้องต้น**: ค้นหา `innerHTML`, `eval`, `document.write`, `outerHTML` ในโค้ดเรา ต้องไม่ใช้กับข้อมูลภายนอก, ตรวจ redirect `next` ว่ากันเว็บนอกจริง, ไม่มี token/รหัสผ่านโผล่ใน console, ตั้ง `<meta name="referrer" content="same-origin">`
6. **ตรวจสถานะ**: ทุกหน้าที่เรียก API ลองด้วย `?mock=slow`, `?mock=error`, `?mock=empty` แล้วแสดงสถานะที่ถูกต้อง
7. **ประสิทธิภาพ**: รันตรวจแบบ Lighthouse (ถ้า AI ทำเองไม่ได้ ให้ผมรันแล้วส่งผล) เป้า: Performance/Accessibility/Best Practices ≥ 90 บนหน้า subjects และ quiz, ฟอนต์ใช้ `display=swap`, ไม่มี JS ที่ไม่ได้ใช้
8. อัปเดต `README.md` ของโปรเจกต์: วิธีรัน, โครงโฟลเดอร์, วิธีเพิ่มภาษาใหม่, วิธีสลับ mock/จริง, รายการ API ที่ใช้

## รายงานที่ต้องส่ง
ตารางสั้น ๆ: หัวข้อตรวจ | ผล (ผ่าน/แก้แล้ว/ยังค้าง) | สิ่งที่แก้ | สิ่งที่ยังค้างพร้อมเหตุผล ห้ามรายงานว่าผ่านถ้าไม่ได้ตรวจจริง
