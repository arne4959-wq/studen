# ขั้น 4 — Login / สมัครสมาชิก / ลืมรหัสผ่าน + ตัวกั้นหน้า

> วางพรอมต์ด้านล่างนี้ให้ AI

---

อ่านกฎกลาง และ `design-ref/Login.html`, `LoginError.html`, `Register.html`, `RegisterError.html`, `Forgot.html`, `DesktopAuth.html` แล้วทำ **ขั้น 4 เท่านั้น**

## งาน
1. สร้างหน้า `login.html`, `register.html`, `forgot.html` และ `js/pages/login.js`, `register.js`, `forgot.js`
   - มือถือ: ตามบอร์ด Login/Register/Forgot
   - จอคอม ≥768px: เลย์เอาต์แบ่งสองฝั่งตาม `DesktopAuth.html` (ซ้ายข้อความสไตล์เทอร์มินัล ขวาฟอร์ม) ปุ่มแท็บ login/register ด้านบนฟอร์มให้เป็นลิงก์ไปสองหน้า ส่วนลืมรหัสผ่านเป็นหน้าแยก
   - ปุ่มสลับธีมและเลือกภาษาอยู่มุมบนขวา (ไม่ต้องมีเมนูล่าง/ข้าง)
2. ฟอร์ม:
   - ใช้ `<form>` + `<label>` จริง, `autocomplete` ที่ถูกต้อง (`email`, `current-password`, `new-password`), `Enter` ส่งฟอร์มได้
   - ตรวจฝั่งหน้าเว็บก่อนส่ง: อีเมลรูปแบบถูก, รหัสผ่าน ≥ 8 ตัว, ยืนยันรหัสผ่านตรงกัน, ชื่อผู้ใช้ไม่ว่าง ข้อความ error ใต้ช่อง (ผูกด้วย `aria-describedby`) และโฟกัสไปช่องแรกที่ผิด
   - ระหว่างส่ง: ปุ่มเป็นสถานะกำลังทำงาน กดซ้ำไม่ได้
   - ผิดจาก API: 401 `invalid_credentials` ➜ กล่อง ERROR บนฟอร์ม + ขอบแดงช่องรหัสผ่าน, 409 `email_taken` ➜ error ใต้ช่องอีเมล, ล้มอื่น ๆ ➜ กล่อง error ทั่วไป
   - forgot: ส่งแล้วเปลี่ยนเป็นกล่อง `✓ ສົ່ງລິ້ງແລ້ວ` มีปุ่ม `resend()`
3. ระบบ session: เก็บ token ใน `store.js` (localStorage), `js/guard.js` มี `requireAuth()` (ไม่มี token ➜ ไป `login.html?next=...`) และ `redirectIfAuthed()` (หน้า login/register ถ้าล็อกอินแล้วไป `subjects.html`) หลังล็อกอินสำเร็จกลับไปที่ `next` (ตรวจว่าเป็นพาธในเว็บเรา ห้าม redirect ไปเว็บอื่น)
4. `index.html`: ตรวจ token แล้วส่งไป `subjects.html` หรือ `login.html`
5. `api.js` ต้อง `reject` เมื่อ 401 ในหน้าที่ต้องล็อกอิน ให้ `guard.js` ตั้ง handler กลาง: ล้าง token แล้วส่งไป login พร้อมข้อความ "เซสชันหมดอายุ"
6. ข้อความทั้งหมดเข้า i18n 3 ภาษา

## ห้าม
- ห้ามเก็บรหัสผ่านที่ไหนเลย, ห้าม log รหัสผ่านลง console
- ห้ามทำหน้าอื่นนอกเหนือจากนี้ (หน้า subjects ฯลฯ ยังไม่ต้อง ให้สร้างหน้าเปล่าชั่วคราวที่มีแค่ `requireAuth()` ถ้าจำเป็นต่อการทดสอบ)
